# Build on Linux

The validated host used clang/LLVM and ld64.lld 23.1.4, Python 3.14.9, fakeroot, Perl and Pillow 13.0.0. Scripts currently call `/usr/bin/clang`, `/usr/bin/ld64.lld` and `/usr/bin/python3`; install the required host tools in those locations or adapt paths deliberately. Apple MapKit/UIKit and Core Location frameworks come from an iOS SDK. No Mac was used for these artifacts.

## Tool locations

- Theos at `.tooling/theos`, revision `8167f59de02fd32cf45b16bfcb1330dfa5c9974c` from https://github.com/theos/theos.
- Procursus ldid at `.tooling/ldid/ldid`, source revision `af86971ae72ec3ed3d0a699107c4e882324c941b` from https://github.com/ProcursusTeam/ldid. Build using that revision's upstream instructions. The local executable hash used for these artifacts is recorded in `BUILD-TOOLS.json`; a different host build need not be byte-identical.
- SDK at `.tooling/theos/sdks/iPhoneOS16.5.sdk`. The archive used was `https://github.com/theos/sdks/releases/download/master-146e41f/iPhoneOS16.5.sdk.tar.xz`, SHA256 `5e0fd3f01266cce4ce012d4a99b38eb56578fca40d09edc81cd83dee958202fb`. The label is 16.5, while internal metadata declares 16.4; this discrepancy was preserved. Obtain/use it under its own applicable terms. SDKs are not GPL and are not included here. This local hash is not an upstream signed checksum.

Install the pinned Python requirements in the environment used by `/usr/bin/python3` (or adapt the interpreter path). Do not install SDK or third-party tool binaries into the Git repository. `BUILD-TOOLS.json` records additional tool hashes; no bit-for-bit reproducibility is promised.

## App and native package

From the repository root, use a new output folder for each build:

```sh
ILL_DIAGNOSTIC_OUTPUT_DIR="$PWD/build/lostgoose-0.3.7" bash scripts/build_diagnostic.sh
python3 scripts/package_app.py \
  --app build/lostgoose-0.3.7/Payload/LocationLabDiagnostic.app \
  --output build/lostgoose-0.3.7/org.lostgoose.app_0.3.7_iphoneos-arm64.deb \
  --report build/lostgoose-0.3.7/deb-build.json
```

The first script creates `LostGoose-0.3.7.ipa`, a base-profile signed app, and a fake-backend diagnostic test executable. Packaging signs a copy with the native profile and validates it. Neither command installs or starts anything on a device. Packaging refuses to overwrite an existing deb. A development build does not establish device compatibility.

The legacy console can be built with `bash scripts/build_engine.sh` and packaged using `make package`. It is separate from the app. Public witness source/build script are included for independent observation.

## Host verification

```sh
python3 tests/test_app_distribution.py
python3 tests/test_native_signing.py
python3 tests/test_bundle_signature.py
```

The latter two require the app/deb produced at the documented paths and the pinned signer. See [validation](VALIDATION.md) for HTTP fixture and device-test prerequisites. Do not run every device script as a host test.

The static-repository generator additionally needs the original text-canary fixture under `build/sileo-repo/`; this fixture is not generated by the app build. It was used for the established Sileo repository. Do not deploy an incomplete folder over a live repository.
